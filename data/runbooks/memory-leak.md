# Runbook: 메모리 누수(Memory Leak) 대응 절차

## 증상
- 메모리 사용률이 재시작 이후 시간에 비례해 꾸준히 올라간다 (트래픽이 줄어도 내려오지 않는다)
- 컨테이너가 `OOMKilled`로 반복 재시작된다
- `java.lang.OutOfMemoryError: Java heap space`가 나고 Full GC 후에도 old gen이 회수되지 않는다
- Full GC 빈도와 pause time이 점점 늘어난다
- RSS가 계속 커지고 swap을 쓰기 시작한다
- 재시작하면 일시적으로 정상이 되지만 몇 시간 뒤 같은 상승 곡선으로 재발한다
- GC 때문에 CPU도 같이 높아지지만 근본 원인은 객체가 쌓이는 것이다 (CPU 급증 절차와 구분)
- 최근 배포에 캐시 무제한 증가, 커넥션 미반환, 리스너 중복 등록 같은 변경이 있었다

## 조치 절차
1. get_monitoring_status로 메모리 사용률 추세(시간에 따라 꾸준히 증가하는지)를 확인한다.
2. OOM 직전(90% 이상)이면 해당 프로세스를 즉시 재시작해 서비스 중단을 막는다 — 재시작은 임시 조치일 뿐임을 기록해둔다.
3. 힙 덤프 또는 프로파일링 도구로 어떤 객체가 계속 쌓이는지 확인한다.
4. 캐시 무제한 증가, 커넥션 미반환, 이벤트 리스너 중복 등록 같은 패턴이 최근 배포에 있었는지 점검한다.
5. 원인이 된 배포가 있으면 롤백하고, 컨테이너 메모리 상한선을 재확인해 재발 시 더 빨리 감지되도록 조정한다.
