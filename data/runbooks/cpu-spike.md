# Runbook: CPU 급증 대응 절차

## 증상
- `CPU utilization above 90%` 알림이 5분 이상 유지되고 load average가 코어 수를 크게 웃돈다
- top/pidstat에서 JVM이나 node 같은 특정 프로세스 하나가 코어를 계속 점유한다
- 스레드 덤프의 대부분이 RUNNABLE 상태다 (WAITING/BLOCKED가 대부분이면 스레드 풀 고갈을 의심)
- 요청량 증가 없이 CPU만 치솟는다: 무한 루프, 정규식 폭주, 직렬화 반복 같은 코드 경로가 의심된다
- 배포 직후 또는 배치 잡이 중복 실행된 시점과 급증 시작 시각이 일치한다
- GC 때문에 CPU가 높더라도 힙이 꾸준히 늘지 않으면 이 절차, 계속 늘면 메모리 누수 절차를 따른다
- steal time(%st)이 올라가면 같은 호스트의 다른 워크로드(noisy neighbor)가 코어를 빼앗는 경우다
- CPU는 낮은데 응답만 느린 경우는 이 절차가 아니라 응답 지연 절차를 본다

## 조치 절차
1. get_monitoring_status로 CPU 사용률과 최근 배포/트래픽 변화 시점을 확인한다.
2. 반복 호출, 배치 작업 중복 실행 같은 특정 요청 패턴이 원인인지 최근 로그에서 확인한다.
3. CPU가 90%를 넘고 지속되면 해당 인스턴스를 오토스케일링 그룹에서 한 대 더 띄워 부하를 분산한다.
4. 급증이 특정 배포 직후 시작됐다면 직전 배포를 롤백하고 원인 분석은 별도로 진행한다.
5. 정상화 후 프로파일링 결과를 바탕으로 핫스팟 코드를 식별해 최적화 작업을 등록한다.
