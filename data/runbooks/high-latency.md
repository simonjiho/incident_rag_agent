# Runbook: 응답 지연(High Latency) 대응 절차

## 증상
- p95/p99 응답시간이 SLO를 넘고 에러율은 낮지만 요청 전반이 느리다 (타임아웃 이전 단계)
- 슬로우 쿼리 로그가 급증하고 DB 커넥션 풀 사용률이 90%를 넘는다
- CPU와 메모리는 정상인데 외부 API 호출 대기 시간만 늘어난다
- 특정 리전이나 인스턴스에만 지연이 몰려 있고 나머지는 정상이다
- 캐시 히트율이 떨어지면서 원본 DB로 가는 요청이 늘었다
- 트래픽 급증 없이 며칠에 걸쳐 응답시간이 서서히 나빠진다
- 지연과 함께 `RejectedExecutionException`이나 503이 보이고 스레드 수가 상한에 붙어 있으면 스레드 풀 고갈 절차를 본다

## 조치 절차
1. get_monitoring_status로 p95 지연시간과 커넥션 풀 사용률을 확인한다.
2. 커넥션 풀 사용률이 90%를 넘으면 풀 크기를 늘리거나 느린 쿼리/외부 호출에 타임아웃을 건다.
3. 지연이 특정 리전/인스턴스에 몰려 있으면 해당 인스턴스를 로드밸런서에서 일시 제외한다.
4. 5분 내 p95가 임계치(1.0s) 아래로 내려오지 않으면 캐시 계층 또는 읽기 복제본으로 트래픽을 분산한다.
5. 정상화 후 느린 쿼리 로그를 분석해 근본 원인을 문서화하고 후속 최적화 티켓을 등록한다.
