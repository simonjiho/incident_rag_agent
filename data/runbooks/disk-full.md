# Runbook: 디스크 용량 부족 대응 절차

## 증상
- `No space left on device` 에러로 파일 쓰기, 로그 기록, DB 체크포인트가 실패한다
- `Filesystem usage above 90%` 알림이 뜨고 사용률이 계속 올라간다
- `df -i`에서 inode 사용률이 100%라서 용량이 남아 있어도 새 파일을 만들 수 없다
- /var/log, /tmp, 컨테이너 overlay 같은 특정 디렉터리가 짧은 시간에 급격히 커진다
- 로그 로테이션이 멈췄거나 디버그 로그 레벨이 켜진 채로 방치돼 있다
- 쿠버네티스에서 `Evicted: ephemeral-storage` 상태로 파드가 쫓겨난다
- 오래된 백업, 덤프, core 파일이 정리되지 않고 누적된다
- DB 볼륨에서 binlog/WAL이 쌓여 데이터 디렉터리가 가득 찼다

## 조치 절차
1. get_monitoring_status와 서버 디스크 사용률을 확인해 임계 수준(90% 이상)인지 판단한다.
2. 로그 파일, 임시 파일, 오래된 백업처럼 안전하게 지울 수 있는 항목부터 정리해 여유 공간을 즉시 확보한다.
3. 특정 프로세스가 비정상적으로 로그를 쌓고 있다면 로그 레벨을 낮추거나 로테이션 주기를 단축한다.
4. 임시 조치로도 부족하면 볼륨을 확장하거나 추가 스토리지를 연결한다.
5. 정상화 후 로그 보존 정책과 디스크 사용률 알림 임계값을 재검토해 조기에 감지되도록 조정한다.
