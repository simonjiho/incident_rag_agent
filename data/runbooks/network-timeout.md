# Runbook: 네트워크 타임아웃 대응 절차

## 증상
- 서비스 간 호출에서 `Read timed out`, `504 Gateway Timeout`이 간헐적 또는 지속적으로 발생한다
- 특정 AZ나 리전 구간에서만 `connection timed out`이 난다
- 패킷 손실과 TCP 재전송(retransmit)이 늘어난다
- 호스트명 해석은 성공하는데 연결 단계에서 대기한다 (DNS 실패와 구분)
- 방화벽이나 보안그룹을 바꾼 직후부터 시작됐다
- 로드밸런서 헬스체크가 실패해 타깃이 unhealthy로 빠진다
- DB는 살아 있고 쿼리도 서버 안에서는 빨리 끝나는데 클라이언트가 응답을 받지 못한다 (락 대기와 구분)
- 429처럼 빠른 거절 응답이 아니라 응답 자체가 오지 않는다 (호출 제한과 구분)

## 조치 절차
1. get_monitoring_status로 어떤 시스템 간 호출에서 타임아웃이 발생하는지 확인한다.
2. DNS 해석 실패, 방화벽/보안그룹 변경, 로드밸런서 헬스체크 실패 중 최근 변경 사항이 있었는지 점검한다.
3. 특정 리전/가용영역에서만 발생하면 해당 구간을 우회하는 라우팅으로 임시 전환한다.
4. 타임아웃 값이 너무 짧아 정상 응답도 실패로 처리되는 경우라면 임계값을 임시 상향해 2차 피해를 줄인다.
5. 정상화 후 네트워크 경로 기록을 남기고, 재발 방지를 위해 헬스체크 주기와 재시도 정책을 재검토한다.
