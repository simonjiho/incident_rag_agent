# Runbook: 호출 제한 초과(Rate Limit) 대응 절차

## 증상
- HTTP `429 Too Many Requests`와 `Retry-After` 헤더가 응답에 보인다
- `ThrottlingException`, `RateLimitExceeded`, `quota exceeded` 같은 외부/클라우드 API 오류가 난다
- 에러가 느리게가 아니라 즉시 돌아온다 (타임아웃은 응답이 아예 오지 않는 것)
- 특정 API 키나 클라이언트 IP에서만 실패하고 다른 호출자는 정상이다
- 분당/일일 쿼터가 초기화되는 시각에 맞춰 실패가 주기적으로 반복된다
- 재시도 폭주(retry storm)로 호출량이 더 늘어 상황이 악화된다
- 서버 쪽 CPU, 메모리, DB 지표는 정상이다
- 배치 잡이나 마케팅 푸시 직후 요청량이 급증한 시각과 일치한다

## 조치 절차
1. get_monitoring_status와 게이트웨이 로그로 429 응답 비율과 제한에 걸린 클라이언트/API 키를 확인한다.
2. 제한을 건 쪽이 외부 API인지 우리 게이트웨이인지 구분하고, 외부라면 남은 쿼터와 초기화 시각(`Retry-After`)을 확인한다.
3. 재시도 폭주(retry storm)가 있으면 지수 백오프와 지터를 적용하고 불필요한 재시도를 즉시 끈다.
4. 급한 경우 쿼터 상향을 요청하거나 큐잉으로 요청 속도를 낮춰 호출량을 평탄화한다.
5. 정상화 후 호출량 급증을 일으킨 배치/캠페인을 확인하고, 클라이언트별 쿼터와 사용량 알림을 재설정한다.
